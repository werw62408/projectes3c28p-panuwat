# พรอมต์ตรวจโค้ดและระบบ SomudTick ทั้งเครื่อง

วิธีใช้: คัดลอกทุกอย่างในกรอบข้างล่างไปวางให้ AI (Claude Code ที่เปิดโปรเจกต์นี้)
ถ้าจะตรวจเวอร์ชันอื่น ให้เปลี่ยน `v11.4` เป็นเวอร์ชันที่ต้องการ
ถ้าจะตรวจแค่บางส่วน ให้ลบข้อที่ไม่ต้องการในส่วน "ขอบเขต" ออก

````
งาน: ตรวจโค้ดและระบบ SomudTick เวอร์ชัน v11.4 ให้ครบทุกอย่างในเครื่อง
โฟลเดอร์: SomudTick_v11.4/SomudTick
อ่าน CLAUDE.md ที่ root ของโปรเจกต์ก่อน แล้วทำตามกฎในนั้นทั้งหมด (ภาษา ลำดับงาน กฎกันกดในกระเป๋า ขาอุปกรณ์)

แบ่งเป็น 2 ช่วง:
- ช่วงที่ 1: ตรวจ + จำลอง + รายงาน ห้ามแก้โค้ดเฟิร์มแวร์ในช่วงนี้
- ช่วงที่ 2: แก้ ทำหลังจากผมตอบว่า "เริ่ม" เท่านั้น

==================== ช่วงที่ 1: ตรวจ ====================

1) อ่านทุกไฟล์ใน SomudTick_v11.4/SomudTick ให้ครบทุกบรรทัด
   (ยกเว้น fonts_th.h ที่เป็นข้อมูลฟอนต์) ห้ามอ่านแค่บางส่วนแล้วเดา

2) ขอบเขต: ตรวจทุกหัวข้อนี้ เขียนผลแยกตามหัวข้อ ข้อไหนไม่เจอปัญหาให้เขียนว่า "ตรวจแล้ว ไม่พบ" พร้อมบอกว่าตรวจอะไร
   ก. เวลา (core_time.h)
      - DS3231: อ่าน/เขียน, บิต OSF, UTC
      - NTP, เวลาจากมือถือ, เวลาที่จำไว้ตอนรีสตาร์ท, เวลาเดา
      - ย้าย log ที่บันทึกตอนเวลายังเดาอยู่ให้ถูกวัน, วันเปลี่ยนตอนเที่ยงคืน, เขตเวลา
   ข. บันทึก (core_log.h, screen_log.h)
      - +1 / − / ยกเลิก, แป้นตัวเลข, หน่วย, เป้าหมาย, แถบเตือน
      - ไฟล์รายวันใน LittleFS, acts.json, ลบแล้วเพิ่มชื่อเดิม, ยอดรวมตลอดกาล, พื้นที่ใกล้เต็ม
   ค. สถิติ (screen_stats.h): All / Days / Hours, cache, ตัวเลขถูกไหม
   ง. ไฟและพลังงาน (core_power.h)
      - จอหรี่ / ดับ, lcd sleep/wakeup, ความเร็ว CPU 80/240 MHz
      - hotspot หลับ, % แบต, LED
   จ. Wi-Fi (core_wifi.h)
      - hotspot + ต่อ Wi-Fi บ้าน, สลับ Home/Uni อัตโนมัติ, สแกน, ต่อใหม่เมื่อหลุด
   ฉ. หน้าเว็บ (web_api.h, webpage.h)
      - ทุก /api
      - PIN: ไม่ถามเมื่อต่อ Wi-Fi บอร์ด, ถามเมื่อต่อ Wi-Fi บ้าน, ล็อก 1 นาทีเมื่อผิด 5 ครั้ง
      - อัปรูปและคลิป (ตัวแปลงคลิปใน JS), ตัวจัดการไฟล์ SD, ถังขยะ
      - ตรวจความปลอดภัยของชื่อไฟล์และ path (../ ชื่อยาว ตัวอักษรแปลก)
   ช. การ์ด SD และสื่อ (app_media.h, backup.h, app_usb.h)
      - Files, ดูรูป, เล่นคลิป + เสียง, Move / Rename / Delete
      - สำรองข้อมูลทุกสัปดาห์, USB drive (TinyUSB MSC)
   ซ. แอป
      - AC Remote (IR): กระแสขา, ส่งซ้ำ
      - Internet: ข่าว / อากาศ / น้ำมัน, งานเบื้องหลัง
      - Bluetooth
   ฌ. เกมทั้ง 6: Pixel Swim, Sudoku, Sand & Water, Habit Garden, Tilt Maze, Blocks
      - กติกาเกม, คะแนนหรือเวลาที่ดีที่สุดถูกเก็บไว้
      - ออกด้วยการกดจอยค้าง 1 วินาที, ตอนจอดับต้องกดถึงจะปลุก
   ญ. จอยสติ๊กและเมนู (joystick.h, nav.h, input.h)
      - ทุกหน้าที่เลื่อนได้ต้องเลื่อนถึงล่างสุดและกลับบนสุดได้
      - กรอบต้องอยู่บนปุ่มที่เห็นทั้งปุ่ม, ทิศหมุนตามจอ 4 ทิศ, หน้าต่างซ้อน (modal)
      - ไม่มีจอยต่ออยู่ ต้องไม่มีสัญญาณรบกวนทำให้กรอบขยับเอง
   ฎ. ทัช: การตั้งค่าทัช (calibration), กดค้าง, เลื่อนด้วยนิ้ว, ปุ่ม BOOT
   ฏ. การวาดจอ (ui_draw.h, ui_main.h, ทุก screen_*.h)
      - ข้อความล้น ถูกตัด หรือทับกัน ทั้งจอแนวตั้งและแนวนอน ทั้งธีมสว่างและธีมมืด
   ฐ. กฎกันกดในกระเป๋า (ดูใน CLAUDE.md): ทุกหน้าและทุกเกมต้องทำตาม
   ฑ. ความทนทานของระบบ
      - millis() วนกลับเป็น 0 (ประมาณ 49 วัน)
      - งาน network task กับ loop() ใช้ตัวแปรหรือสาย I2C พร้อมกัน
      - เขียน flash บ่อยเกินไป (prefs.put… ใน loop), หน่วยความจำรั่ว หรือ heap แตกเป็นชิ้น
      - บัฟเฟอร์ล้น, String ยาว, JSON ใหญ่, การ์ด SD หลุดกลางทาง, Wi-Fi หลุดกลางทาง, ไฟตก
   ฒ. การอัปเดต: ข้อมูลจากเวอร์ชันเก่า (prefs, log, ไฟล์ในการ์ด) ต้องใช้ต่อได้ และตารางแบ่งพื้นที่ต้องไม่เปลี่ยน

3) จำลองก่อนสรุปทุกครั้ง: ทุกบั๊กที่คิดว่าเจอ ต้องพิสูจน์ในตัวจำลอง
   - เฟิร์มแวร์:
     - cd tools/sim && ./run_tests.sh ../../SomudTick_v11.4/SomudTick
       (ถ้ายังไม่เคยใช้ ให้รัน ./setup.sh ก่อน) ของเดิมต้องผ่านทั้งหมด
     - เขียนไฟล์ทดสอบใหม่ tools/sim/review_v11.4.cpp ให้ทำอาการของแต่ละบั๊กเกิดซ้ำ
       ต้องขึ้น FAIL ก่อนแก้ ถ้าทำให้เกิดซ้ำไม่ได้ ให้บอกตรง ๆ ว่า "ยังไม่ยืนยัน"
     - ถ่ายภาพทุกหน้าจอ ทั้งจอแนวตั้งและแนวนอน (tools/sim/shots.sh, sheet.py) แล้วดูภาพจริงทีละภาพ เพื่อหาข้อความล้นหรือถูกตัด
     - ใช้จอยจำลองเลื่อนทุกหน้าจนสุดแล้วกลับขึ้นมา
     - เล่นทุกเกมด้วยจอยจำลอง
     - ทดสอบตอนจอดับ: โยกจอยหรือแตะจอแล้วต้องไม่มีอะไรเกิดขึ้นนอกจากจอติด
     - จำลองสถานการณ์สุดขั้วตามรายการใน CLAUDE.md ทุกข้อ (เปิดเครื่องนาน, เวลากระโดด, ที่เก็บเต็ม, ถอดการ์ด, Wi-Fi หลุด, แตะรัว, ข้อมูลเยอะมาก, เปิดครั้งแรก)
   - หน้าเว็บ:
     - node tools/web/test_video.js SomudTick_v11.4/SomudTick/webpage.h
     - ถ้าตรวจ JS ส่วนอื่น ให้เปิดหน้าเว็บใน Chromium (Playwright) โดยจำลองบอร์ดแบบเดียวกับไฟล์นี้
   - บอร์ดจริง: สร้าง bin ด้วย tools/build_firmware.sh ต้องคอมไพล์ผ่าน
     แล้วเทียบตารางแบ่งพื้นที่ (ไบต์ที่ 0x8000) กับเวอร์ชันก่อน ต้องเหมือนกัน

4) รายงานช่วงที่ 1 (ภาษาไทย):
   - ตารางบั๊ก: ลำดับ | ความรุนแรง (ข้อมูลหาย / เครื่องค้าง / ใช้งานผิด / เล็กน้อย) | ไฟล์:บรรทัด | อาการที่ผู้ใช้เห็น | วิธีทำให้เกิดซ้ำ | ยืนยันในตัวจำลองแล้วหรือยัง
   - เรียงจากรุนแรงมากไปน้อย แยกรายการ "ยืนยันแล้ว" กับ "สงสัย ยังยืนยันไม่ได้"
   - ทางแก้ที่เสนอสำหรับแต่ละข้อ
   - ส่วนที่พิสูจน์ในตัวจำลองไม่ได้ ต้องลองบนบอร์ดจริง พร้อมบอกวิธีลอง
   - ภาพหน้าจอที่มีปัญหา (รวมเป็นแผ่นเดียว)
   จากนั้นหยุดรอผมตอบ ห้ามเริ่มแก้เอง

==================== ช่วงที่ 2: แก้ (หลังผมตอบว่า "เริ่ม") ====================

5) ทำเวอร์ชันใหม่ตามที่ CLAUDE.md กำหนด:
   - สร้างโฟลเดอร์ใหม่, เปลี่ยนเลขเวอร์ชันในหน้า About
   - แก้ทุกข้อที่ผมเลือก
   - แก้เสร็จ ทดสอบใน review_v11.4.cpp ต้องเปลี่ยนเป็น PASS ทุกข้อ และชุดทดสอบเดิมต้องผ่านทั้งหมด
   - ถ่ายภาพหน้าจอใหม่แล้วตรวจอีกรอบ
   - สร้าง bin, README ส่วน "ของใหม่" พร้อม ✅/❌, ตารางคำศัพท์, รูปตัวอย่าง, zip, commit + push
6) สรุปผลเป็นภาษาไทย บอกสิ่งที่ต้องลองบนบอร์ดจริง แล้วรอคุยก่อนทำรอบต่อไป
````

## หมายเหตุ
- ตัวจำลองทำแทนบอร์ดจริงได้หลายอย่าง แต่ยังเหลือเรื่องที่ต้องลองบนบอร์ดจริงเสมอ:
  - ความเร็วจอ, USB drive, การแฟลช, เสียง
  - ระยะยิง IR, ความรู้สึกตอนโยกจอย, สัญญาณ Wi-Fi จริง, ไฟแบตจริง
- การโหลดข่าวและอากาศในตัวจำลองใช้เน็ตจริง บางครั้งโหลดไม่สำเร็จ ถ้าข้อทดสอบนั้นพลาด ให้รันซ้ำก่อนสรุปว่าเป็นบั๊ก
