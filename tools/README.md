# เครื่องมือของ SomudTick

โฟลเดอร์นี้เก็บเครื่องมือสำหรับตรวจและสร้างเฟิร์มแวร์ ผู้ใช้บอร์ดไม่ต้องใช้ ใช้เฉพาะตอนแก้โค้ด

## 1. ตัวจำลองบนคอม (`sim/`)
คอมไพล์โค้ด `SomudTick.ino` ตัวจริงบนคอม Linux แทนฮาร์ดแวร์ด้วยของจำลอง (ไฟล์ใน `stubs/`) แล้วใช้ทำ 2 อย่าง:
- **ทดสอบ:** รันขั้นตอนต่าง ๆ แล้วเช็คผล เช่น กด +1 แล้วกด - ยอดรวมต้องกลับเท่าเดิม
- **ถ่ายภาพหน้าจอ:** บันทึกทุกหน้าจอเป็นไฟล์ PNG ไว้ดูว่าข้อความล้นหรือตกขอบไหม

### ใช้งาน
```
cd tools/sim
./setup.sh                                          # ครั้งแรกครั้งเดียว: โหลด LovyanGFX 1.2.30 + ArduinoJson 7.4.2
./run_tests.sh ../../SomudTick_v11.2/SomudTick      # รันทุกการทดสอบ
./shots.sh shots_v11.cpp ../../SomudTick_v11.2/SomudTick run/shots   # ถ่ายภาพหน้าจอ
python3 sheet.py out.png 4 run/shots/*.png          # รวมภาพหลายภาพเป็นแผ่นเดียว
```
✅ ต้องเห็นบรรทัดสุดท้ายเป็น `ALL TESTS PASSED`
❌ ถ้าเห็น `BUILD FAILED` ให้เปิดไฟล์ `run/<ชื่อ>.build.log` ดูข้อผิดพลาด

### ไฟล์
| ไฟล์ | คืออะไร |
|---|---|
| `sim_common.h` | ส่วนกลาง: ตั้งค่าเวลาจำลอง ใส่ข้อมูลตัวอย่าง 14 วัน ใส่รูปตัวอย่างในการ์ด SD และฟังก์ชันบันทึกภาพ |
| `test_*.cpp` | ชุดทดสอบของแต่ละเวอร์ชัน แต่ละบรรทัดที่พิมพ์ออกมาลงท้ายด้วย PASS หรือ FAIL |
| `shots_*.cpp` | สคริปต์ถ่ายภาพหน้าจอ |
| `stubs/` | ของจำลองแทน Arduino, Wi-Fi, การ์ด SD, หน้าเว็บ, บลูทูธ, นาฬิกา DS3231 |
| `deps/`, `obj/`, `bin/`, `run/` | ของที่สร้างขึ้นเอง ไม่เก็บใน git |

ข้อจำกัด: ในตัวจำลอง งานเบื้องหลัง (โหลดข่าว สแกนบลูทูธ) ทำเสร็จทันที และการโหลดข่าวใช้เน็ตจริงผ่าน curl ส่วน USB drive, การแฟลช และความเร็วจอจริง ต้องทดสอบบนบอร์ดเท่านั้น

## 2. สร้างไฟล์เฟิร์มแวร์ (`build_firmware.sh`)
```
ARD=/path/to/arduino-cli ARD_DATA=/path/to/arduino-data ./build_firmware.sh ../SomudTick_v11.2/SomudTick
```
ได้ไฟล์ `SomudTick_merged.bin` สำหรับแฟลชที่ตำแหน่ง 0x0 ไฟล์นี้**ไม่เติมเต็ม 16 MB** จึงไม่ทับพื้นที่เก็บ log
